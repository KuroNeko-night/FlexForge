# FlexForge 安全基线

**版本**：v1.0
**状态**：active（P01 起生效）
**日期**：2026-08-20
**适用范围**：`backend/`、`frontend/`、`database/`、`plugins/`、`tests/`、`scripts/` 与 CI 的全部安全要求

> 本文是应用安全的唯一归属文档：收拢既有文档中的安全决策并引用出处；本文首次定义的数值（密码哈希强度、锁定阈值、解压文件数上限等）以本文为唯一来源，其他文档只引用不复制。违反安全红线（§2）按治理违规 P0 处理（`AGENTS.md` §5）。

## 1. 威胁模型

**保护资产**：用户凭据与角色数据、动态业务数据、元数据配置、插件包与激活记录、模型 API 密钥、审计日志。

**主要攻击面与威胁**：

| 攻击面 | 威胁 | 主防线 |
| --- | --- | --- |
| 动态数据 API | SQL 注入、越权读写 | 白名单字段映射 + 参数化（S1、`docs/08` §5） |
| 登录接口 | 暴力破解、用户枚举 | 失败锁定 + 统一错误（§3.1） |
| 插件上传 | zip-slip、zip 炸弹、恶意资源 | 声明式白名单校验（S6、`docs/09` P07） |
| 前端动态渲染 | XSS | 白名单 renderer + CSP（S5、§3.4） |
| 插件代码处理器（Level 2，2026-09-04） | 恶意脚本、资源耗尽、注入输出 | ADMIN 特权导入 + 子进程隔离/超时/IO 上限 + 输出 Schema 校验（S6、ADR-0002 §Level 2） |
| AI 链路 | 提示词注入、密钥泄漏 | Schema 校验 + 密钥后端隔离（S7、§3.6） |
| 依赖与构建 | 供应链投毒 | 锁文件 + 漏洞扫描（§3.9） |
| 权限边界 | 水平/垂直越权 | 服务端 RBAC（S2、§3.2） |

**明确不防（超出毕业设计范围）**：APT 与定向渗透、DDoS、多租户隔离（本项目无多租户）、浏览器恶意扩展、物理与社会工程攻击。答辩陈述时如实说明。

## 2. 安全红线（S1-S9）

与 `docs/10-engineering-governance.md` 的 R 系列同级；违反任一条按 P0 处理，不得提交。

- **S1 输入必经校验**：所有外部输入（API 参数、元数据、插件资源、AI 输出）在边界处校验；动态 SQL 的表名/列名只来自 `MetaRegistry` 白名单映射，值一律参数化绑定（对齐 `docs/10` R3、`FR-META-05`）。
- **S2 服务端授权**：每个 API 在服务端校验角色与对象权限；前端隐藏菜单/按钮只是体验，不是安全边界。
- **S3 凭据慢哈希**：密码只存 bcrypt（cost ≥ 10）或 Argon2id；禁止明文、可逆加密、MD5/SHA-1/无盐哈希。
- **S4 密钥零暴露**：JWT 密钥只经环境变量注入；模型 API key 经环境变量**或**管理员设置页录入（P15 起第二条受控通道，语义见 §3.6-5：AES-256-GCM 加密落库、读接口只回掩码）。密钥不得出现在仓库、日志、错误响应、API 明文出参或前端产物中。
- **S5 前端无动态执行**：禁 `v-html`/`eval`/`new Function`；渲染只走白名单 renderer（对齐 `docs/coding-standards.md` §3）。
- **S6 插件资源双轨校验（2026-09-04 修订，ADR-0002 Level 2 激活）**：Level 1 包只接受声明式资源、无任何代码文件；Level 2 包额外允许 `scripts/*.py` 且**仅**经 `extension.data-processor` 声明执行——上传包全链路校验（Schema、路径、大小、资源类型）不变。处理器执行边界：子进程 `python3 -I` + 环境清空 + 临时目录执行后清理 + 硬超时 kill + stdin/stdout 字节上限 + 输入行数上限=平台单页上限（200）+ stdout JSON 输出 Schema 校验；超时/非零退出/非 JSON/超限统一 `processor_failed` 族错误码且必有失败路径测试。处理器进程环境无平台注入的凭据键（DB_/AUTH_/FLEXFORGE_，测试实证）、执行串行（Semaphore）；**披露**：`-I` 仅隔离解释器配置，受信脚本仍可访问运行用户文件系统与网络——信任根=ADMIN 导入者，非多租户边界（ADR-0002 Level 2 表）；调用（invoke）与动态数据读同权（ADMIN/USER），导入仍 ADMIN 特权。原"无任意代码"语义收窄为"无平台内代码执行"（脚本只在受控子进程跑数据计算）。
- **S7 AI 输出是数据不是指令**：模型输出必须通过 JSON Schema 校验与资源白名单才可进入系统；输出中的"指令性内容"一律不执行。
- **S8 脱敏**：日志与错误响应不含密码、令牌、密钥、完整 Authorization 头、堆栈、SQL 与内部路径（对齐 `docs/coding-standards.md` §5、R-GOV-08）。
- **S9 最小暴露**：Actuator 仅暴露 health；CORS 禁止通配 `*`；调试端点不进入演示/交付配置。

## 3. 分域基线

### 3.1 认证与会话

1. 密码哈希用 `BCryptPasswordEncoder`（cost ≥ 10）或 Argon2id；哈希与盐由库托管，不自造实现。
2. 登录防暴破：同一用户名连续失败 **5 次**锁定 **10 分钟**（单实例内存实现即可）；锁定与解锁写入审计。
3. 登录失败返回统一错误（"用户名或密码错误"），不区分用户是否存在，防用户枚举。
4. JWT：算法固定 HS256 且密钥为 ≥ 256 位随机值（env 注入）；payload 只放用户 ID、角色标识与时间；TTL 按环境配置，演示环境覆盖完整演示时长（对齐 `docs/09` P03）。
5. **自助注册（P13 新增）**：匿名端点 `POST /auth/register`——开关 `flexforge.auth.self-registration-enabled`（默认开，feature flag）+ 单 IP 滑动窗口限流（默认 5 次/小时，内存口径、不采信 X-Forwarded-For；**反向代理部署下全体客户端共享 remoteAddr 聚合为一个桶**，仅限直连/单用户演示场景）+ 与管理建号同款用户名/口令/显示名校验；引导管理员用户名保留（注册拒绝同名，防空库窗口抢注毒化 AdminBootstrap——**部署顺序约定：先引导管理员再开放注册**）；重名 400 构成有界用户名枚举面（限流限界，与管理建号同暴露水平，记为已接受）；新账号固定 USER 角色；注册成功即签发令牌（等价登录）；审计 `auth.register` success/failure（failure=限流触发或并发重名接管阻断，PR #33 审查 P2-1 口径）。
6. **账号停启用（P13 新增）**：`PUT /system/users/{id}/status`（ADMIN，不可操作自己，操作者须为 ACTIVE——阻断 BLOCKED 管理员凭存量令牌互停）；BLOCKED 拒绝新登录与 `/me`；**已接受的风险**：BLOCKED 用户已持有的 JWT 在 TTL 内仍有效（无状态令牌，与第 7 条登出口径同族，短 TTL 缓解，答辩如实陈述）。
7. **已接受的风险（MVP 不做，答辩如实陈述）**：JWT 服务端吊销与刷新令牌轮换；登出 = 前端删除令牌 + 审计事件，令牌在 TTL 内仍有效的窗口由短 TTL 缓解；按用户名锁定可被恶意用于锁定已知账号（账号 DoS，锁定到期被动失效、锁定事件有审计，P03 复审确认接受）；用户名枚举的时序侧信道（统一错误消息但响应时间差约一次 BCrypt，Issue #10 排期以 dummy 哈希拉平）。

### 3.2 授权

1. RBAC 校验集中在 api 层（注解或拦截器统一声明），禁止散落在业务方法里的手写权限判断。
2. 对象级访问（Issue 详情、插件版本等）必须校验归属或角色，防水平越权。
3. 动态数据访问必须校验实体启用状态与权限（对齐 `FR-META-04`）；插件停用后其数据 API 对普通用户拒绝（对齐 `FR-PLUGIN-05`）。
4. 插件预设（P21，FR-PLUGIN-12）全套端点仅 ADMIN；应用=对既有 activate/stop/upgrade 的编排（审计、占用检查、幂等口径不变），预设本身只新增 name 输入面（非空、长度 ≤50、重名拒绝），不引入新资源解析或代码执行面。

### 3.3 输入校验与注入防护

1. 所有请求 DTO 使用 Bean Validation 在 api 层校验（非空、长度、格式）；未过校验的输入不进领域层。
2. 动态查询：排序/筛选字段白名单、`pageSize ≤ 200`、`pageNumber` 1..100000（OFFSET 溢出防线，`PageQuery` 中央实现）；JSONB 查询构造只允许登记过的操作符集合。
3. 用户输入不拼接 SQL、命令或文件路径（`NFR-SEC-02`）。

### 3.4 前端与 XSS

1. 用户内容一律文本插值渲染；MVP 不提供富文本（`docs/02` 未定义富文本字段类型）。
2. CSP：生产构建启用基础策略（`default-src 'self'` 起步，按需放宽并在本文登记）；开发环境如需放宽（Vite HMR）仅限 dev 配置。
3. Token 存储 tradeoff（已决策，2026-08-25 P06 落地口径）：MVP 用 `sessionStorage`（刷新可恢复、关标签即清，残留面小于 localStorage）+ 短 TTL + 严格 XSS 防护（S5 + CSP）；不引入 HttpOnly Cookie（避免连带 CSRF 防护范围）。答辩被问时按此口径回答。

### 3.5 插件包与文件上传

1. 上传接口仅管理员可用（对齐 `FR-PLUGIN-02`）；包校验全链路以 `docs/09` P07 为准（压缩 ≤ 10 MB、解压 ≤ 50 MB、zip-slip、路径与脚本资源拒绝、临时目录清理）。
2. 本文补充（数值以本节为唯一来源）：解压后文件数量 ≤ **1000**；解压必须流式进行并累计字节数，超限立即中止，不得解压完成后再检查；文件名拒绝控制字符与超长路径。
3. 上传时校验 Content-Type 并做魔数嗅探，不信任客户端文件名与类型声明。
4. 插件资产 serve（P08）：响应头固定 `Content-Security-Policy: default-src 'none'` + `Content-Disposition: attachment` + `X-Content-Type-Options: nosniff`（svg 事件属性纵深，与 §3.5-3 导入期魔数/文本嗅探构成两层防御）；按 activationId 做 stale 校验，路径为存储键精确匹配（无文件系统访问面）。

### 3.6 AI 链路

1. AI 权限边界以 `docs/03` §6 为准：无数据库、shell、文件系统与发布权限。
2. 提示词注入防护：用户输入嵌入提示词时视为数据段；模型输出只作为"待校验数据"处理，其中任何指令性内容（如要求读取文件、修改权限的文字）不执行。提示词模板版本化（prompts/v2 起，P21）：v2 增补提问功能调用策略与回复边界条款，数据段口径与本条不变。
3. 模型密钥只在后端 `ModelPort` 实现内使用，永不经 API 出参或前端往返（对齐 `docs/09` P11）。
4. 模型响应必须通过 Schema 校验与资源白名单（`FR-ISSUE-04`）；校验失败的输出不得生成任何可安装产物。
5. **模型运行时配置（P15 设置页，用户裁决）**：`GET/PUT /ai/config`（ADMIN）持久化 provider=fixture|http、base-url、model 与 API Key；密钥经 `SecretCipher`（AES-256-GCM，密钥=HMAC-SHA256(`AUTH_JWT_SECRET`, 域分隔标签) 派生）加密后落 `ai_provider_config` 单行表——密钥材料仍以环境变量为根，数据库泄露不直接泄露 API Key；任何读路径只回 `apiKeyConfigured` 布尔与尾 4 位掩码，明文仅存在于加密前内存与 `Authorization` 头（S8：不进日志/任务记录，`ai_task_log` 口径不变）；`AUTH_JWT_SECRET` 轮换后旧密文不可解，按"未配置"降级并提示重新录入（不静默用旧值）；有效配置解析顺序=DB 行 > 环境变量（`FLEXFORGE_AI_*`）> 默认 fixture；审计 `ai.config` 记操作者与结果（不含密钥材料）。

### 3.7 密钥与敏感数据

1. 密钥纪律、`.env.example` 与受保护内容以 `docs/repository-maintenance.md` §4/§9 为准。
2. 演示与种子数据一律使用虚构信息（不出现真实姓名、学号、手机号、邮箱）。
3. fixture 不含真实密钥与个人信息（对齐 `docs/11` §5）。

### 3.8 传输、CORS 与响应头

1. MVP 默认 `localhost` HTTP（本机开发与本机演示可接受）。
2. 跨机演示（答辩投屏等）需启用反向代理 HTTPS（自签或内网证书），在 P14 演示机固化时实施。
3. CORS：开发用 Vite dev proxy 保持同源；部署态同源或确切域名白名单，禁止 `allowedOrigins("*")`。
4. 响应头基线：`X-Content-Type-Options: nosniff`、`X-Frame-Options: DENY`；错误响应不带服务器版本与内部细节。
5. Actuator 仅暴露 `health`（如需 `info` 单独登记理由）；management 端点不对外监听。

### 3.9 依赖与供应链

1. 锁文件必须提交；新增依赖说明用途、许可证与替代方案（对齐 `docs/repository-maintenance.md` §6）。
2. 依赖漏洞扫描（本节新增要求）：前端 `npm audit`、后端启用 Dependabot alerts 或 OWASP dependency-check；纳入 `scripts/check-repo-health` 报告项。高危漏洞（CVSS ≥ 7.0）7 天内修复，或开 Issue 登记豁免理由与复查时间。
3. 不引入无维护、来源不明的包；Docker 基础镜像固定版本。前端图表依赖 chart.js（MIT，canvas 绘制、构建期内置无运行时外链，P22 图表基建；替代方案 ECharts 体积过大、手搓 canvas 不可维护，均不采纳）。

### 3.10 数据库与迁移

1. 应用连接不使用超级用户：开发与演示环境均使用专用账号（如 `flexforge_app`），不授予 `SUPERUSER`/`CREATEROLE`。
2. 账号分离（P05 起实施）：迁移执行账号（DDL 权限）与应用运行账号（DML 权限）分离，插件迁移 runner 越界时的损害范围由此受限。
3. 插件迁移 runner 越界拒绝与 checksum 规则以 ADR-0005 为准。
4. 测试只连一次性 schema/临时容器，禁止指向开发库与演示库（对齐 `docs/04` §2）。
