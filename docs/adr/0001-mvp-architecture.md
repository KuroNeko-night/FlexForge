# ADR-0001：MVP 采用模块化单体与声明式插件

**状态**：Accepted  
**日期**：2026-08-20

## 背景

FlexForge 需要同时验证元数据驱动、插件生命周期和 AI 生成闭环。微服务会增加部署、鉴权、数据一致性和调试成本；任意后端代码插件又会引入沙箱和安全问题，超出毕业设计的可控范围。

## 决策

MVP 使用前后端分离的模块化单体。后端按领域模块组织，但共用一个应用进程和数据库。插件采用声明式资源包，只允许元数据、菜单、权限、视图、迁移和已登记扩展点；不执行任意上传代码。

## 影响

### 正面影响

- 本地和答辩环境部署简单，端到端调试成本低。
- 事务、权限、审计和插件安装更容易保持一致。
- 可以先证明核心机制，再在未来拆分服务或开放扩展点。

### 负面影响

- 单体进程的隔离性和独立伸缩能力有限。
- 声明式插件无法覆盖所有复杂业务，需要预先设计扩展点。
- 部分“自动生成后端代码”的原始设想被收敛为“生成配置和骨架”。

## 备选方案

1. **微服务**：不采用。对个人毕业设计的部署和运维成本过高，不能直接提升核心验证价值。
2. **任意代码插件 + 沙箱**：不采用。需要权限模型、资源限制、隔离运行时和安全审计，风险与工作量都不匹配。
3. **完全静态业务页面**：不采用。无法证明元数据驱动和插件复用的创新点。

## 复审条件

当出现以下情况时重新评估：插件需要独立扩展且模块边界稳定；系统需要多实例部署；或已有可靠的隔离运行时和签名机制。
