# FlexForge MVP 需求规格

## 1. 用户角色

| 角色 | 目标 |
| --- | --- |
| 普通用户 | 使用已安装的业务模块，提交和跟踪 Issue。 |
| 开发者 | 配置元数据、审核需求、生成和测试插件。 |
| 管理员 | 管理用户角色、插件生命周期和系统审计。 |

## 2. 功能需求

### 认证与权限

- `FR-AUTH-01` 用户可以使用用户名和密码登录、退出。
- `FR-AUTH-02` API 使用 JWT 认证；过期令牌被拒绝。
- `FR-AUTH-03` 管理员可以为用户分配角色；接口和菜单按权限可见。
- `FR-AUTH-04` 管理员可以分页浏览审计日志并按操作者/动作/对象过滤（消费 P03 审计查询 API，前端页面与菜单仅 ADMIN 可见；时间窗过滤 UI 为候选，P24）。
- `FR-AUTH-05` 管理员可以批量停用/启用账号：单请求批量变更（单事务、逐用户审计、上限 100、不可包含自己、未知用户 404、操作者须为启用状态——与单人路径同守卫，P24）。
- `FR-AUTH-06` 用户管理列表默认隐藏 BLOCKED 账号（前端过滤，后端契约不变），提供"显示已封禁"开关（P26 界面净化）。

### 元数据与动态 CRUD

- `FR-META-01` 开发者可以创建、编辑、停用实体。
- `FR-META-02` 实体支持文本、整数、小数、日期、枚举、布尔六类字段。
- `FR-META-03` 开发者可以配置列表列、查询字段和表单顺序。
- `FR-META-04` 用户可以对启用实体执行查询、新增、编辑、删除和详情查看。
- `FR-META-05` 所有字段名、类型、长度和校验规则必须经过白名单校验。
- `FR-META-06` 实体列表可导出 XLSX（与 CSV 同口径：前端本地生成、可见列与当前已加载记录一致、无新端点；P23）。

### 插件

- `FR-PLUGIN-01` 插件包必须包含符合 Schema 的 `plugin.json`。
- `FR-PLUGIN-01A` 插件包必须声明能力等级、平台版本范围、依赖和不可变版本标识。
- `FR-PLUGIN-02` 管理员可以导入、校验、安装、启用、停用和卸载插件。
- `FR-PLUGIN-03` 安装过程注册元数据、菜单和权限，并记录版本。
- `FR-PLUGIN-04` 安装失败时不得留下半完成的注册信息。
- `FR-PLUGIN-05` 停用插件后其菜单和 API 不可用于普通用户。
- `FR-PLUGIN-06` 系统记录稳定插件 ID、插件版本 ID 和每次激活尝试 ID。
- `FR-PLUGIN-07` 使用过期激活身份的 API 请求必须被拒绝，并返回可诊断错误。
- `FR-PLUGIN-08` Level 1 声明式插件只能使用白名单字段类型、renderer、扩展点和迁移操作。
- `FR-PLUGIN-09` 插件可以通过登记扩展点添加、更改与移除 GUI 部件（如功能按钮、记录动作、菜单项），撤销后界面无残留入口。
- `FR-PLUGIN-10` 插件可以声明界面布局（页面/工作台槽位与部件编排），运行时按声明渲染；不提供可视化拖拽式 GUI 设计器（历史概念稿远期方向，不属于本项目需求——2026-08-24 用户澄清）。
- `FR-PLUGIN-11` 插件可以携带并更换美术资产（背景图、图标、动画），资产只经包校验白名单（类型/大小/路径，S6）分发与引用，更换即时生效、卸载恢复默认外观。
- `FR-PLUGIN-12` 管理员可以把当前启用插件集合保存为命名预设（含版本），并一键应用：系统先停用预设外的启用插件，再按预设切换/激活（P21；逐项执行，单项失败不中断并逐项上报）。
- `FR-PLUGIN-14` Level 2 数据处理器可声明文件输入（inputMode=file + 扩展名白名单 + 大小上限）：用户上传表格文件经扩展名/魔数/大小三重校验后交给脚本处理（argv[1]=输入路径、FLEXFORGE_OUTPUT_DIR=输出目录），脚本输出文件产物（kind=file）登记为临时产物（归属创建者、TTL 过期清理），经归属校验的下载端点获取；执行边界与错误码族与既有处理器一致（P23，S6 修订）。
- `FR-PLUGIN-15` 插件管理列表默认折叠已停用插件（前端过滤，后端契约不变），提供"显示已停用"开关（P26 界面净化）。

### Issue 与 AI

- `FR-ISSUE-01` 用户可以创建 Issue、评论、加标签和指派。
- `FR-ISSUE-02` Issue 状态遵循 `待审核 -> 已批准 -> 待测试 -> 测试通过 -> 已完成`，允许退回修改和开发失败。
- `FR-ISSUE-03` AI 通过多轮追问补齐实体、字段、视图、权限和验收标准。
- `FR-ISSUE-03A` 澄清助手在信息不足时必须优先输出追问（每轮至多 3 个、具体可答）而不是猜测成规格；回复边界限定当前 Issue 的声明式插件需求，输出仅双态 JSON（P21，提示词 v2）。
- `FR-ISSUE-03B` 信息足够时澄清助手产出三段式简报并随规格版本落库：口语化需求确认（面向用户）、结构化规格（RequirementSpec v1，面向开发者）、可行性说明与插件制作提示词（面向开发者/agent）；提示词 v3，双态输出契约保留（P23）。
- `FR-ISSUE-07` Issue 界面按角色分置（服务端收口，S2）：普通用户只见对话工作台——与 AI 澄清对话、查看自己的已发布需求（可折叠侧栏）并参与讨论、对自己 Issue 执行"确认并推送"（需存在有效最新规格，幂等）；开发者/管理员保留完整信息面（列表/状态机/三段简报分区），且 agent 提示词可复制；普通用户的列表与评论范围限本人创建（P23）。
- `FR-ISSUE-04` AI 输出必须符合版本化 JSON Schema，用户可以修改后确认。
- `FR-ISSUE-05` 确认后的规格可以生成声明式插件骨架，并进入测试环境。
- `FR-ISSUE-06` 模型不可用时，用户可以手工编辑规格并继续后续流程。
- `FR-ISSUE-08` 平台提供配套的插件开发 Agent Skill（单文件 SKILL.md：包结构/清单/实体/视图/迁移/处理器/打包校验/导入激活全链教学，与校验器口径一致），开发者可在 Issue 简报卡下载后连同 agent 提示词交给实现 AI（P24）。
- `FR-ISSUE-09` 需求工坊（P30）：整合页 Issue 模式为对话式创建——开场输出模板引导文案；用户对话描述，AI 追问至信息足够后**经提示词工具调用协议创建 issue**（双态 JSON：{"reply"} 追问 / {"tool":"create_issue","title","description"} 执行）；工具面收敛于服务端 WorkshopTool 接口（预留扩展，未知工具按非法输出重试后 400）；title（≤120）/description（≤4000，P30 起服务端统一强制）复用既有创建校验、creator=认证用户；模型回复落库 ≤8000 码点安全截断；创建后以对话摘要跑澄清链路落规格草稿+三段简报（失败降级"已创建未成规格"不回滚）；确认推送仍是用户动作；工坊会话按用户隔离存储、可清空（V021）。

### 平台与设置（P15 用户裁决新增）

- `FR-SETUP-01` 管理员可以在设置页配置 AI 模型运行时参数（provider=fixture|http、base-url、model、API Key）；API Key 加密存储，任何读接口不回显明文（docs/13 §3.6-5）；配置即时生效，模型不可用时手工规格路径不受影响（FR-ISSUE-06）。http 配置保存时探活上游（GET {base}/models 带 Bearer）：不可达/非 2xx/超时/密钥无效/模型不在列表 → 保存失败 400 报错上抛（含上游原因）且不落库；base-url 为根地址（自动拼 /chat/completions，OpenAI/DeepSeek 官方口径），旧"完整端点"存量值向后兼容；保存路径出站 URL 守卫拒绝环回/私有/保留地址（P26）。
- `FR-SETUP-02` 用户可以在设置页切换界面语言；语言内容以插件分发（locale 资产），插件停用后回退平台中文基线。语言包只覆盖系统界面 chrome（导航/标题/按钮/表头/空态/提示），插件内容（插件名/菜单 label/实体名/字段名/数据值）不翻译（P26 口径）。

### 知识库与 AI 助手（P28 用户裁决新增）

- `FR-KB-01` 知识库条目：管理员可随时创建、编辑、删除知识条目（标题+分类+正文纯文本），尺寸上限标题 ≤120、分类 ≤40、正文 ≤20000 字符（超限 400）；条目对登录用户可读（列表全量倒序、上限 200）；删除经前端统一确认对话；写操作仅 ADMIN（S2 服务端收口），增删改全程审计。
- `FR-KB-02` 关键词检索注入：助手提问经分词评分（标题命中计 ×2、正文 ×1，多词问题需 ≥2 个不同命中词共现佐证）取 Top-K（K≤5）条目注入提示词，单条注入 ≤1500 字符、总注入 ≤6000 字符；无命中条目时不注入任何条目（置无命中占位标记）且回答应说明知识库暂无相关资料（不得编造）。
- `FR-KB-03` AI 助手：登录用户可在助手页提问，回答由模型基于知识库检索结果生成并附引用条目（标题+分类）；会话按用户隔离存储（仅本人可见、可清空），多轮上下文注入（近 8 条、合计 ≤4000 字符）；模型调用唯一经 ModelPort（http/fixture 路由与设置页配置一致），fixture 供应商产出确定性引用式回答（无外部依赖可演示）；提示词文件化（kb-assistant-v1），知识内容与提问以数据段嵌入（docs/13 §3.6-7）；标题与分类禁换行（防伪造知识段条目行）。
- `FR-KB-04` 失败路径与安全：非 ADMIN 写条目 403；尺寸超限 400；模型不可用或返回空回复 503 model_unavailable 上抛且不落半截会话（用户消息与回复要么同落要么全不落）；kb.ask 成败同口径审计（含落库失败）；知识条目内容不进入日志与错误消息。
- `FR-KB-05` 助手对话附件（P29）：提问可附带文件（白名单 png/jpg/jpeg/gif/webp/pdf/csv/xlsx/docx/txt/md；单文件 ≤10MB、单次 ≤3 个，超限 400）；附件随消息存储（仅本人可下载，404 防枚举）；服务端提取文本注入提示词数据段（txt/csv/md 直读、docx/xlsx 标准库 zip+XML 提取带炸弹防护、pdf 经 PDFBox，单文件提取 ≤20000 字符、注入总预算 ≤20000 字符；图片仅存储与展示不进提示词）；提取失败降级为"仅存档"不阻断问答；附件与消息同事务（模型失败附件同回滚）；提示词升 kb-assistant-v2。
- `FR-KB-06` 助手与 Issue 工作台整合（P29）：AI 助手页演进为整合页——左右滑动分段开关切换"AI 助手"（知识库问答）与"Issue 工作台"（复用 FR-ISSUE-07 用户端对话工作台整体：可折叠需求提交侧栏+新需求表单+澄清对话+三段简报+确认推送+讨论区）两模式；平台 Issue 工作台菜单收窄为 DEVELOPER+ADMIN（纯 USER 的需求入口=整合页 Issue 模式），纯 USER 直访 /issues 重定向整合页；issues 服务端契约零变化。
- `FR-KB-07` 助手业务工具（P30 用户补充）：助手可在提示词协议内调用只读工具了解业务插件内容——`list_entities`（业务实体清单）与 `inspect_entity`（按实体名查字段结构，经 MetaRegistry 只读）；提示词含平台生成的业务实体索引数据段；工具调用以 {"tool":...} JSON 形态识别、每问 ≤2 次、结果仅作数据段回灌（不执行模型输出的任何指令）；工具面为平台内置 AssistantTool 扩展位，插件作者无需写代码——实体/字段 displayName 质量即适配（见开发 Skill §7.5）；未知工具/参数错误以错误文本回灌不中断对话。

### 示例业务

- `FR-DEMO-01` 提供一个库存示例，至少包含物料编码、名称、库存数量和状态。
- `FR-DEMO-02` 库存示例使用动态 CRUD 和至少一条可验证的业务规则（例如库存数量不得小于 0）。
- `FR-DEMO-03` 库存示例只能以 Level 1 插件包交付（`plugins/example-inventory`），预置但不自动安装；管理员可通过插件管理对其停用、启用、卸载，流程与第三方插件完全相同，无硬编码开关或内置路径。

## 3. 非功能需求

- `NFR-SEC-01` 所有写操作记录操作者、时间、对象和结果。
- `NFR-SEC-02` 用户输入不得直接拼接 SQL、命令或文件路径。
- `NFR-OPS-01` Docker Compose 可以启动完整开发环境。
- `NFR-OPS-02` 数据库迁移可重复执行，失败可定位。
- `NFR-UX-01` 加载、空数据、校验失败、无权限和服务异常均有明确界面反馈。

### 图表基建

- `FR-CHART-01` 平台提供图表渲染基建（条形图/饼图）：图表由平台组件以白名单方式渲染（canvas，无插件前端代码），配色走平台结构令牌、主题插件可覆盖，reduced-motion 下动画归零（P22）。
- `FR-PLUGIN-13` Level 2 数据处理器可以输出图表数据（kind=chart：chartType=bar|pie + categories/values），经平台 Schema 校验后由图表基建渲染；违约返回 processor_output_invalid（输出契约只增不改）。
- `NFR-TEST-01` 主流程具备自动化冒烟测试。
- `NFR-PLUGIN-01` 每个插件注册项都能在停用或卸载时撤销，不允许残留菜单、权限和监听器。
- `NFR-MAINT-01` 代码满足 `docs/coding-standards.md` §7 的文件长度与复杂度硬约束，由 CI 阻断违规。
- `NFR-MAINT-02` 任何新扩展点或服务 seam 必须先登记到 `docs/extension-points.md`，并具有注册/撤销测试。
- `NFR-SKEL-01` 系统骨架不含任何业务能力：空库执行平台迁移后没有业务菜单、实体或页面；所有业务（含演示库存）都通过插件注册，并可在插件管理中停用/卸载。

## 4. 验收场景

### 场景 A：动态实体

给定管理员已登录，开发者创建“物料”实体并配置四个字段；当实体启用后，普通用户可以在菜单中打开列表、新增一条记录、编辑并查询该记录。

### 场景 B：插件生命周期

给定一个合法插件包（第三方或预置的库存示例均适用），管理员导入后校验通过；安装后菜单、权限和元数据可用；停用后访问被拒绝；再次启用恢复；卸载后注册信息清理且审计日志完整。

### 场景 B2：插件失败与过期激活

给定一个缺少依赖或迁移失败的插件，系统返回明确失败阶段并回滚已完成注册；给定一个已经停用的旧 `activationId`，其 API 请求被拒绝且不影响当前插件版本。

### 场景 C：Agent Issue

给定用户描述“需要管理物料库存”，AI 至少追问字段、校验、权限和验收标准；用户确认规格后生成插件骨架；开发者审核、安装并测试成功，Issue 完成。

### 场景 D：骨架纯净性与业务可关闭

给定一个只执行平台迁移的干净数据库，系统启动后没有任何业务菜单、实体和页面；安装预置库存插件后出现库存功能；通过插件管理停用后不可访问；卸载后菜单、权限和注册信息无残留。
