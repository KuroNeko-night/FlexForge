# 编码与注释规范

## 1. 通用原则

- 优先写清晰、可测试的代码，避免为了复用而抽象。
- 一个函数只承担一个可描述的职责；跨层业务规则放在应用服务或领域服务。
- 不用异常控制正常分支；错误必须包含可定位的业务上下文。
- 外部输入在边界处校验，内部对象使用明确类型。
- 代码、接口和数据库字段使用英文命名；面向用户的文案使用中文。

## 2. 后端约定

- 类名使用 `PascalCase`，方法和变量使用 `camelCase`，常量使用 `UPPER_SNAKE_CASE`。
- Controller 只负责协议转换和权限声明，不编排复杂业务。
- DTO、命令对象和领域对象分离；禁止把数据库实体直接作为公开 API 响应。
- 跨模块公开接口必须标注 `@PublicApi`（稳定）或 `@ExperimentalApi`（可变更，注明变更窗口）；未标注视为内部实现，禁止被其他模块 import。
- 数据访问必须参数化；动态表名和列名只能来自已校验的元数据映射。
- 事务边界放在应用服务；插件安装和迁移必须具备明确的失败语义。

## 3. 前端约定

- Vue 组件使用 `PascalCase.vue`，组合式函数使用 `useXxx.ts`。
- 页面负责组合，通用组件负责复用，API 调用集中在 service 层。
- 所有异步请求处理 loading、empty、error 和 permission denied 状态。
- 动态渲染器不得把未经校验的元数据直接当作 HTML 或脚本执行。
- 禁止对元数据或用户内容使用 `v-html`、`eval`、`new Function`；一切渲染走白名单组件。

## 4. 注释规范

只在“为什么这样做”不明显时写注释，禁止重复描述代码行为。

```java
// Keep plugin registration and migration in one transaction so a failed
// migration cannot leave menus or permissions pointing to a partial plugin.
@Transactional
public void install(PluginPackage pkg) { ... }
```

适合写注释的场景：安全边界、兼容性 workaround、复杂算法不变量、事务/重试语义、与外部系统的约束。以下内容不写注释：变量赋值、显而易见的 getter/setter、逐行翻译代码、已经在方法名和类型中表达清楚的内容。

## 5. API 与日志

- API 文档必须说明鉴权、请求示例、成功响应、错误码和幂等性。
- 日志使用结构化字段，包含 request ID、业务对象 ID 和结果。
- 严禁记录密码、令牌、完整 Authorization 头、API key 和未脱敏个人信息。
- 日志级别遵循 `ERROR`（需要处理的失败）、`WARN`（可恢复异常）、`INFO`（关键业务事件）、`DEBUG`（本地诊断）。
- 时间一律以 UTC 存储（`Instant` / `timestamptz`），对外 JSON 使用 ISO-8601 含时区，前端负责本地化显示；禁止用 `LocalDateTime.now()` 落库。
- API 错误响应不向客户端泄漏堆栈、SQL 或内部路径；完整堆栈只进服务端日志。

## 6. 代码审查清单

- 是否有对应需求编号和测试？
- 是否验证权限、输入和失败路径？
- 是否引入不必要的动态执行、反射或全局状态？
- 是否更新接口、数据库、插件格式和文档？
- 是否会破坏已有迁移、演示脚本或回滚流程？
- 文件长度、圈复杂度、参数和嵌套是否满足 §7？是否有未登记扩展点或绕开 registry 的新实现路径？
- 新能力是注册到既有 seam/扩展点，还是另开了一条重复实现路径？

## 7. 结构与复杂度硬约束（唯一数值来源）

> 本表是文件长度与复杂度约束的唯一事实来源；`docs/10-engineering-governance.md`、CI 配置与审查清单只引用本表，不复制数值。行数统计口径以对应工具为准（Checkstyle `FileLength` / ESLint `max-lines`，含空行与注释）。

| 约束 | 后端 Java/Kotlin | 前端 Vue SFC | 前端 TS/JS |
| --- | --- | --- | --- |
| 单文件长度：硬上限 / 建议目标 | 400 / 250 行 | 350 / 250 行 | 300 / 200 行 |
| 函数/方法长度 | ≤ 40 行 | — | ≤ 50 行 |
| 圈复杂度 | ≤ 10 | ≤ 10（`<script>` 内） | ≤ 10 |
| 参数个数 | ≤ 5 | — | ≤ 5 |
| 嵌套深度 | ≤ 3（`NestedIfDepth`） | — | — |
| SQL 迁移文件 | ≤ 300 行；一个迁移只做一件事（适用于全部数据库迁移） | — | — |

执行规则：

1. CI 对硬上限报 error（阻断合并）；对建议目标报 warn（评审必须说明，不阻断）。
2. 圈复杂度、参数个数、嵌套深度不允许豁免；超出必须重构，不得用 suppression 绕过。
3. 文件长度豁免：文件顶部写 `// SIZE-WAIVER(<issue 号>, <一句话原因>, <评审人>)`（Vue 用 `<!-- SIZE-WAIVER(...) -->`），并在同一 PR 提交对应 lint suppression 配置。每个里程碑复盘时必须重新论证；累计豁免超过 3 处，必须开一个重构 Issue。
4. 拆分必须按职责拆（拆类、拆组件、拆组合式函数），禁止"文件拆小但函数依旧超长"的假拆分。
5. 新增代码从第一个提交起即纳入统计；任何阶段结束时不允许存在违反硬上限的新增文件。
